# Lua 101

Lua in one sitting, using `tab.lua` as the textbook. Every snippet
below is real code from that file, so when you finish you can read
all 563 lines of it.

Lua is small: eight types, one data structure, no classes, no
modules keyword, no `self` keyword that you cannot rename. The
whole language fits in your head, which is why `tab.lua` has no
dependencies.

Run it:

    luajit tab.lua            # the help text
    luajit tab.lua --all      # the unit tests
    luajit tab.lua --num      # just one test

## 1. Eight types

`nil boolean number string table function userdata thread`.

That is all. No arrays, no classes, no records, no sets -- those are
all `table`. `type(x)` tells you which:

```lua
if type(f) ~= "function" then ... end
```

Two rules cover most beginner surprises:

- **Only `nil` and `false` are false.** `0` is true. `""` is true.
- **Numbers are one type.** In Lua 5.1/LuaJIT every number is a
  double; in 5.3+ there are integer and float subtypes, but `1` and
  `1.0` still compare equal. `tab.lua` runs on both.

## 2. Variables

Variables are global unless you say `local`. Globals live in a
table, which turns out to matter -- see [modules](#10-modules).

```lua
local min = require "tab"           -- tab-eg.lua
floor, exp, sqrt, log = math.floor, math.exp, math.sqrt, math.log
abs, min, max = math.abs, math.min, math.max
```

Those last two lines are **multiple assignment**: names and values
in parallel. Parallel means you can swap without a temporary, which
is the whole of Fisher-Yates:

```lua
function shuffle(t,    j)           -- in place, Fisher-Yates
  for k = #t, 2, -1 do j = rint(k); t[k], t[j] = t[j], t[k] end
  return t end
```

If there are fewer values than names, the rest are `nil`. If more,
the extras are discarded. No error either way.

Assignment is a statement, never an expression, so `if x = 1` will
not compile. Lua spares you that bug class.

## 3. Tables: the only data structure

A table is a hash map that gives integer keys a fast path. Use the
integer part as an array, the rest as a record -- often both at
once, as `BAG` does:

```lua
function Bag()                      -- blank counts, for one test set
  return new(BAG, {n = 0, ok = 0, got = {}, want = {}, hit = {}}) end
```

Three ways to write the same key:

```lua
i.has[v]        -- bracket, computed key
i.has.c         -- dot, literal key: sugar for i.has["c"]
{has = {}}      -- in a constructor
```

**Arrays start at 1.** `#t` is the length of the array part:

```lua
i.cols[#i.cols + 1] = col           -- the push idiom
```

`#t` is only meaningful when the array has no holes. Put a `nil` in
the middle and `#t` may report either side of it. This is why `map`
builds its output with `u[#u+1] = ...` and skips nils rather than
writing to `u[k]`:

```lua
function map(t,f,    u)      -- f(v,k) over t,in order; nils are dropped
  u={}; for k, v in ipairs(t) do u[#u+1] = f(v, k) end
  return u end
```

That dropping is used on purpose -- it makes `map` a filter too:

```lua
t = map({1,2,3,4}, function(v) return v % 2 == 0 and v or nil end)
assert(#t == 2 and t[1] == 2 and t[2] == 4)        -- nils drop
```

Missing keys return `nil`, never an error. Hence the standard
"default zero" counter, which is all of `SYM.add`:

```lua
function SYM.add(i,v)               -- one more of v
  if v == "?" then return end
  i.n = i.n + 1
  i.has[v] = (i.has[v] or 0) + 1 end
```

The same `or` trick memoizes in one line -- compute once, keep it
on the instance, and `nil` means "not yet":

```lua
i.kinds = i.kinds or max(2, sum(i.has, f))
```

Tables are **references**. Passing one to a function does not copy
it, so a function that sorts its argument damages the caller's
list. `tab.lua` takes that seriously:

```lua
function TAB.split(i,    rows,n,t,u1,u2) -- never shuffles i.rows
  rows   = shuffle(map(i.rows, same))    -- itself
```

`map(t, same)` -- map with the identity function -- is the shallow
copy idiom.

## 4. Strings

Concatenate with `..` (not `+`):

```lua
cache = (os.getenv"HOME" or "~") .. "/tmp/cache"
```

Strings are immutable and interned. Multi-line literals use double
brackets and need no escaping, which is how the whole help text
*and* the default settings live in one string:

```lua
the,help = {}, [[
tab.lua: a good guess from a few dozen labels.
...
flags:
  bins=7           numeric columns get this many bins
  m=2              m-estimate: prior weight for a thin bin
]]
```

That string is then read back as the config, so a default can never
drift from its documentation -- there is only one copy:

```lua
for k, v in help:gmatch"\n%s+(%a+)=(%S+)" do the[k] = thing(v) end
```

Any string has the `string` library as methods, so `s:sub(1,1)`
works on a literal too:

```lua
if s ~= "" and s:sub(1, 1) ~= "#" then ...
("%d,%.4f,%s\n"):format(s, os.clock() - t0, line)
```

**Sugar:** a call with one string or one table literal needs no
parentheses. `tab.lua` leans on this everywhere:

```lua
os.getenv"HOME"                     -- os.getenv("HOME")
s:match"^%s*(.-)%s*$"               -- s:match("^%s*(.-)%s*$")
i:add"?"                            -- i:add("?")
Tab{ {"Age","job","klass!"} }       -- Tab({ {"Age",...} })
order{"a","a","b"}                  -- order({"a","a","b"})
```

`tonumber(s)` returns `nil` when `s` is not a number, so the whole
"is this cell a number?" question is one line:

```lua
function thing(s)                   -- one cell: number, or the string
  s = s:match"^%s*(.-)%s*$"; return tonumber(s) or s end
```

## 5. Control flow

```lua
if     k     then the[k] = thing(v)       -- looked like name=value
elseif eg[s] then eg[s]()                 -- looked like an action
else              the.file = s end        -- must be a file
```

`elseif` is one word; every block ends with `end`; there is no
`switch` -- use a table of functions, as [section 6](#6-functions)
does.

Three loops:

```lua
while p < #xs and xs[p+1] == v do p = p + 1 end    -- while

for k = #t, 2, -1 do ... end             -- numeric: from, to, step
for s = 1, reps do ... end

for _, col in order(i.cols) do col:add(row[col.at]) end   -- generic
for k, v in pairs(t) do ... end
for v in (s .. ","):gmatch"(.-)," do ... end
```

`ipairs` walks `1,2,3...` until the first `nil`. `pairs` walks
every key in no defined order. The difference is load-bearing in
`tab.lua`: `map` uses `ipairs` because rows are ordered, `sum` uses
`pairs` because it adds up symbol counts:

```lua
function sum(t,f,    n)             -- f(v,k) over t's items, added up
  n=0; for k, v in pairs(t) do n = n + f(v, k) end; return n end

sum(i.has, f) / log(2)              -- entropy, over a symbol count
sum(i.y, f)                         -- over an array of goal columns
```

`repeat ... until cond` exists. `break` exists. `continue` does
not; invert the test instead. Lua 5.2+ has `goto`, which `tab.lua`
never uses.

Comments are `--` to end of line, or `--[[ ... ]]` for a block.

## 6. Functions

Functions are values: store them in tables, pass them, return
them. `tab.lua`'s whole test suite is a table of functions, which
is also its command line:

```lua
eg  = {}                           -- cli runs eg[action]; see --all
eg["--thing"] = function()
  assert(thing" 42 " == 42 and thing"x" == "x") end
```

...dispatched by name, with no `if` chain in sight:

```lua
elseif eg[s] then eg[s]()
```

**Missing arguments are `nil`**, which gives you default arguments
for free:

```lua
function Num(txt,at)                -- no args: an anonymous num
  txt, at = txt or "N", at or 0
```

**Multiple returns** need no tuple type:

```lua
function BAG.parts(i,x,    tp,fp,fn) -- x's tp, fp, fn, tn, so far
  ...
  return tp, fp, fn, i.n - fn - fp - tp end

tp, fp, fn, tn = i:parts"a"
```

Two rules govern them. A call expands to all its results only in
the **last** position of a list; anywhere else it is cut to one.
And parentheses around a call cut it to one. Both are load-bearing:

```lua
return (best(i.subs, f))     -- best gives key,score. Want the key.
io.lines((file:gsub("^~", os.getenv"HOME" or "~")))  -- gsub gives 2
ok, line = pcall(fun, pair(tbl, s))  -- pair gives 2; both expand
```

The second one matters: `gsub` returns the new string *and* a
count, and `io.lines` would otherwise read that count as a second
argument.

Functions defined inside functions capture the enclosing locals.
`tab.lua` uses that to pass a *goal* around, so one learner serves
any objective you can write as a function of a row:

```lua
y     = function(row) return sub:ydist(row) end
model = Rmeans(tbl, few, y)
```

Note the odd-looking parameter lists -- `function sum(t,f,    n)`.
The names after the gap are not arguments anyone passes; they are
locals, declared as parameters so they arrive as `nil`. It is a
house style that keeps functions short and documents their working
set. See [luamore.md](luamore.md#4-parameters-as-locals).

## 7. Errors: assert and pcall

`assert(cond, msg)` raises when `cond` is false. The test suite is
built from almost nothing else, with floats compared through a
tolerance and never `==`:

```lua
function near(a,b) return abs(a - b) < 1e-6 end

assert(i.n == 10 and i.mu == 5.5 and near(i:div(), 3.0276503541))
```

`pcall(f, ...)` is Lua's entire try/catch: it returns `true` plus
`f`'s results, or `false` plus the error.

```lua
ok, line = pcall(fun, pair(tbl, s))     -- a broken csv is a skip
if not ok then h:close(); os.remove(f); error(line, 0) end
```

That pattern is worth copying whole: catch, **clean up the
half-written file**, then re-raise. Without the `os.remove`, a
crash would leave a truncated csv that the next run would happily
accept as finished work. The `0` in `error(msg, 0)` suppresses the
usual `file:line:` prefix, so a re-raised message is not stamped
twice.

## 8. Patterns, not regexps

Lua has its own small matcher. It is not POSIX, not PCRE. Classes
use `%`, not `\`:

| pattern | means                    | pattern | means              |
|---------|--------------------------|---------|--------------------|
| `%a`    | letter                   | `%s`    | space              |
| `%d`    | digit                    | `%u`    | uppercase          |
| `%w`    | letter or digit          | `%S`    | not space          |
| `.`     | any char                 | `%%`    | a literal `%`      |

Quantifiers are `*` (greedy), `+` (greedy, 1+), `-` (**lazy**,
0+), `?` (optional). There is no alternation (`|`) and no `{n,m}`.

Anchors `^` and `$`, captures in `( )`:

```lua
k, v = s:match"^(%a%w*)=(.*)$"      -- two captures, two returns
s = line:match"^%s*(.-)%s*$"        -- trim: %s*(.-)%s* is the idiom
col = (txt:find"^%u" and Num or Sym)(txt, at)   -- find: truthy or nil
if txt:find"[-+!]$" then ...
file:match"([^/]+)%.csv$"           -- basename
```

That third line is worth a second look: `and`/`or` pick a
*constructor*, and the result is immediately called. An uppercase
first letter means the column is numeric.

The four verbs:

- `s:match(p)` -- the captures, or `nil`
- `s:find(p)` -- start and end indices, or `nil` (pass `true` as a
  4th argument for plain, pattern-free search)
- `s:gsub(p, r)` -- the replaced string, and a count
- `s:gmatch(p)` -- an iterator over every match

That last one, over a long string, is the whole csv cell splitter:

```lua
function cells(s,    row) row = {}
  for v in (s .. ","):gmatch"(.-)," do row[#row + 1] = thing(v) end
  return row end
```

## 9. Methods, metatables, and no inheritance

There are no classes. There is one piece of sugar: `a:f(x)` means
`a.f(a, x)`. So a "method" is just a function whose first argument
is the receiver.

`tab.lua` defines methods with a dot and an explicit receiver named
`i` (most Lua code uses `:` and the implicit name `self` -- the dot
form is the same thing, written out):

```lua
function NUM.add(i,v,    d)         -- Welford's running mean and sd
  if v == "?" then return end
  i.n = i.n + 1
  d = v - i.mu
  i.mu = i.mu + d / i.n
  i.m2 = i.m2 + d * (v - i.mu) end
```

...and calls them with a colon:

```lua
i = Num(); for x = 1, 10 do i:add(x) end
assert(i.n == 10 and i.mu == 5.5)
```

How does `i` know about `NUM.add`? A metatable holds handlers for
what a table cannot answer itself, and `__index` is the
failed-lookup hook. That is the whole object system, in one line:

```lua
function new(meta,i)                -- i is now one of meta's kind
  meta.__index = meta; return setmetatable(i, meta) end
```

So the class is a plain table, and "what kind is this?" is
literally its metatable:

```lua
assert(getmetatable(t.cols[1]) == NUM)       -- A-Z: num; a-z: sym
assert(getmetatable(t.cols[4]) == SYM)
```

Constructors are plain functions in Camel case, one per ALLCAPS
class table -- naming is the entire type system here:

```lua
TAB,NUM,SYM,BINS,RMEANS,NB,BAG,SAME = {},{},{},{},{},{},{},{}

function Num(txt,at) ... return new(NUM, {...}) end
function Sym(txt,at) ... return new(SYM, {...}) end
```

**And there is no inheritance.** Every class metatable points at
itself, one level deep. `NUM` and `SYM` are unrelated tables that
merely answer the same four messages -- `add`, `div`, `norm`,
`bin`:

```lua
function NUM.div(i)                 -- standard deviation
  return i.n < 2 and 0 or sqrt(i.m2 / (i.n - 1)) end

function SYM.div(i,    f)           -- entropy
  f = function(n) return -n/i.n * log(n/i.n) end
  return sum(i.has, f) / log(2) end

function SYM.bin(i,v) return v end  -- a sym is its own bin
function SYM.norm(i,v) return v end -- syms pass through
```

Two of those are one-liners that return their argument. That is the
price of duck typing, and it is cheaper than a hierarchy, because
no caller ever branches on type:

```lua
for _, col in order(i.cols) do col:add(row[col.at]) end
```

If you *do* want inheritance it is one more line -- point the
subclass's `__index` at the superclass instead of at itself.
`tab.lua` declines, on the grounds that one level is enough.

Other metamethods exist (`__add`, `__eq`, `__lt`, `__call`,
`__tostring`, `__newindex`) and would let you write `num1 + num2`.
`tab.lua` uses none of them: operator overloading hides where the
work happens.

## 10. Modules

`require "x"` looks for `x.lua` along `package.path` and returns
whatever that file returns. It caches, so the file runs once no
matter how many others ask for it.

`tab.lua` returns its own environment:

```lua
return _ENV
```

...which is everything the file defined, with no export list to
keep in sync. That works because of the two lines at the very top:

```lua
local _ENV = setmetatable({}, {__index = _G})
if setfenv then setfenv(1, _ENV) end   -- lua 5.1, luajit
```

In Lua 5.2+ every global `x` compiles to `_ENV.x`. Rebind `_ENV`
and "global" means your table: writes land there, reads miss and
fall through `__index` to the real globals. So the file gets the
whole standard library and leaks nothing of its own. Lua 5.1 and
LuaJIT have no `_ENV` but do have `setfenv`, hence the second line,
guarded so it is a no-op on 5.2+.

The rig then adopts that table as *its* globals:

```lua
package.path = (arg[0]:match"^(.*)/" or ".") .. "/?.lua;" .. package.path
local min = require "tab"
if setfenv then setfenv(1, min) end          -- tab's _ENV is ours too
local _ENV = min
the = cli()                         -- tab's options, off our cli
```

Now `Tab`, `Nb` and `the` need no prefix. It is also sharp-edged --
two files, one namespace, no record of who owns what -- so for a
library with several consumers prefer the plain `local M = {}; ...
return M`. [luamore.md](luamore.md#14-modules-return-_env) has the
longer argument.

Being both a script and a library takes one guard, Lua's
`if __name__ == "__main__"`:

```lua
if (arg and arg[0] or ""):find"tab%.lua$" then
  if #arg == 0 then eg["-h"]() else cli() end end
```

`arg` is the command line: `arg[0]` is the script's own name,
`arg[1]` the first argument, `#arg` the count.

## 11. The standard library `tab.lua` actually uses

Small enough to list:

```lua
math.floor  math.exp  math.sqrt  math.log  math.abs
math.min    math.max              -- all cached as locals, line 27

table.sort(u, f)        -- IN PLACE, unstable; f(a,b) is "a before b"
table.concat(t, ",")    -- array to string; numbers and strings only

tonumber(s)  tostring(x)  type(x)  assert(cond, msg)  pcall(f, ...)
setmetatable(t, meta)   getmetatable(t)   pairs(t)   ipairs(t)

io.open(f, "w")  h:write(s)  h:close()  io.lines(f)  print(...)
os.clock()  os.getenv"HOME"  os.execute(cmd)  os.remove(f)
string.format(...)   or   ("%d,%.4f,%s\n"):format(...)
arg                     -- the command line; arg[0] is the script
```

Time things with `os.clock` (cpu seconds), never `os.time` (wall
clock, one-second resolution):

```lua
t0  = os.clock()
...
tot = tot + (os.clock() - t0) end
```

And note what is **missing**: `math.random`. Its generator differs
between Lua builds, platforms and versions, so results would not
reproduce. `tab.lua` ships its own Park-Miller instead:

```lua
function rint(n)                    -- 1..n, repeatable from the.seed
  the.seed = (16807 * the.seed) % 2147483647
  return 1 + floor(n * the.seed / 2147483647) end
```

The arithmetic peaks near 3.6e13, under 2^53 (~9.0e15), the largest
integer a double holds exactly. So Lua, Python and Lisp all shuffle
a table into the same order, and a train/test split becomes a
number you can quote in a paper rather than a file you have to
ship.

## 12. Sharp edges

1. **Indices start at 1.** `t[1]` is the first item, `t[#t]` the
   last, `t[0]` is just another key.
2. **`~=`, not `!=`.** And `not`, `and`, `or` -- no `!`, `&&`,
   `||`.
3. **`..` concatenates, `+` is arithmetic.** `"a" + 1` is an error;
   oddly, `"2" + 1` is 3 (strings coerce to numbers in arithmetic).
4. **`0` and `""` are true.** `if n then` is not `if n > 0 then` --
   the most common Lua bug for Python and C refugees.
5. **No `++` or `+=`.** Write `i.n = i.n + 1`.
6. **A `nil` in an array breaks `#`.** Append with `t[#t+1]` and
   never store `nil` as a value you plan to count.
7. **Undeclared variables are global and silently `nil`.** A typo
   reads as `nil` rather than raising. The `_ENV` sandbox of
   [section 10](#10-modules) stops `tab.lua`'s globals leaking into
   everyone else's, but it does not catch typos.
8. **Integer division is `//` in 5.3+ only.** `tab.lua` uses
   `floor(a / b)` so it runs everywhere.
9. **`pairs` order is undefined.** `best(i.subs, f)` walks a hash,
   so an exact tie is broken by internal table layout. Summing a
   hash of floats depends on addition order in the last bit, too.
10. **`table.sort` is in place and unstable**, and a comparator that
    is not a strict weak ordering can raise "invalid order
    function" or corrupt the array. Plain `<` errors on mixed
    types.
11. **`t[1]` and `t["1"]` are different keys.** Everything off a
    csv goes through `thing` once, at the edge, so the type is
    settled there.
12. **Instance fields shadow class methods.** `new(NUM, {div = 3})`
    makes `i:div()` a call on a number. Keep constructor keys and
    method names disjoint.
13. **Shadowing is silent.** `same`, `Same` and `SAME` are three
    different things in `tab.lua`; case is the only convention
    keeping them apart.
14. **`and`/`or` return a value, not a boolean.** This is a feature,
    and `tab.lua` uses it as a ternary:

    ```lua
    w = txt:find"%-$" and 0 or 1
    z = z > 3 and 3 or (z < -3 and -3 or z)
    return i.n < 2 and 0 or sqrt(i.m2 / (i.n - 1))
    ```

    The trap: `cond and 0 or 1` works, but `cond and false or 1`
    always yields 1, because `false` is falsy. Never put `false` or
    `nil` in the middle slot.
15. **`setfenv` exists only on 5.1/LuaJIT, `_ENV` only on 5.2+.**
    Code for both writes `tab.lua`'s first two lines, and tests on
    both.
